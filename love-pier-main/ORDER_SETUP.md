# ระบบสั่งเดลิเวอรี + LINE + QR PromptPay — คู่มือเปิดใช้งาน

ระบบสั่งซื้อถูกฝังอยู่ในเว็บ (หน้า `/delivery`) เรียบร้อยแล้ว เหลือแค่กรอกค่า 3 อย่างเพื่อเปิดใช้งานครบทุกฟีเจอร์

## 1. สร้างตารางในฐานข้อมูล (ทำครั้งเดียว)
รันไฟล์ [`lib/db/orders.sql`](lib/db/orders.sql) ใน Supabase → SQL Editor
> ✅ รันให้แล้วในระบบจริง — ตาราง `orders` และ `customers` พร้อมใช้งาน

## 2. ตั้งค่า Environment variables
เติมค่าใน `.env.local` (และใน Vercel → Project → Settings → Environment Variables):

| ตัวแปร | ได้จากไหน | จำเป็น |
|--------|-----------|--------|
| `NEXT_PUBLIC_PROMPTPAY_ID` | ตั้งไว้ `010554511741402` (Biller ID บริษัท เลิฟเพียร์ จำกัด) | ✅ เพื่อให้ QR ทำงาน |
| `NEXT_PUBLIC_PROMPTPAY_TYPE` | ตั้งไว้ `biller` (QR บิลเพย์เมนต์นิติบุคคล) — เว้นว่างถ้าใช้เบอร์/บัตร | ✅ คู่กับ ID ด้านบน |
| `NEXT_PUBLIC_LIFF_ID` | LINE Developers → LINE Login channel → แท็บ LIFF (เช่น `2010601364-AbCdEfGh`) | ทางเลือก — เปิดปุ่ม "เข้าสู่ระบบด้วย LINE" |
| `NEXT_PUBLIC_LINE_OA_ID` | LINE OA basic ID (มี @ นำหน้า) ปัจจุบันตั้งไว้ `@891jhcya` | ✅ ปุ่มส่งสลิป |

> **QR เป็นแบบ Bill Payment (Biller ID) ของนิติบุคคล** — เงินเข้าบัญชีบริษัทโดยตรง และแนบเลขอ้างอิง (payment_ref เช่น `LPMR8WG1S9`) ไว้ในทุก QR + บันทึกในตาราง orders → ร้านเช็คยอดเงินเข้าตรงกับออเดอร์ได้จาก Ref บน statement
>
> ⚠️ **ก่อนใช้จริง: สแกน QR ที่เว็บสร้างด้วยแอปธนาคารเพื่อยืนยันว่าขึ้นชื่อ "บริษัท เลิฟเพียร์ จำกัด" และยอดถูกต้อง** (ไม่ต้องกดจ่าย แค่ดูว่าปลายทางถูก)

> ระบบออกแบบให้ทำงานได้แม้ยังไม่ตั้ง LIFF ID — ปุ่ม LINE จะถูกซ่อน ลูกค้ากรอกข้อมูลเองได้ปกติ

## Flow การสั่งซื้อ (4 ขั้น อยู่ใน `components/CartDrawer.js`)
1. **ตะกร้า** — เพิ่ม/ลดรายการ
2. **ข้อมูลจัดส่ง** — ชื่อ/เบอร์/ที่อยู่ + ปุ่ม LINE Login (เติมชื่อ+ที่อยู่เดิมอัตโนมัติสำหรับลูกค้าเก่า)
3. **ชำระเงิน** — QR PromptPay สร้างจากยอดในตะกร้าอัตโนมัติ
4. **สำเร็จ** — แสดงเลขออเดอร์ + ปุ่มส่งสลิปทาง LINE

## การยืนยันการชำระเงิน
ตอนนี้เป็นแบบ **ส่งสลิปทาง LINE** (ฟรี ไม่มีค่าธรรมเนียม) ออเดอร์บันทึกสถานะ `pending`
อนาคตถ้าต้องการยืนยันอัตโนมัติ ต่อ payment gateway (Omise / GB Prime Pay / LINE Pay) ได้ โดยเพิ่ม webhook อัปเดต `orders.status = 'paid'`

## แจ้งเตือนออเดอร์ใหม่เข้า LINE ร้าน (ทางเลือก)
ทุกครั้งที่มีออเดอร์ใหม่ ระบบจะ push ข้อความสรุปเข้า LINE ร้านได้ ต้องตั้ง 2 ค่า:

| ตัวแปร | ได้จากไหน |
|--------|-----------|
| `LINE_MESSAGING_TOKEN` | LINE Developers → channel **Messaging API** ของ OA → **Channel access token (long-lived)** → Issue |
| `LINE_ORDER_NOTIFY_TO` | ปลายทางที่จะรับแจ้งเตือน — **1 id หรือหลาย id คั่นด้วยจุลภาค (สูงสุด 5)** ผสม `U…` (แชทส่วนตัว), `C…` (กลุ่ม), `R…` (ห้องแชท) ได้ |

**วิธีหา `LINE_ORDER_NOTIFY_TO`:**
- **ส่งเข้าตัวเอง (เจ้าของร้าน):** แอด OA เป็นเพื่อน → ใน LINE Developers → Messaging API → เลื่อนหา **"Your user ID"** = userId ของคุณ → ใช้ค่านี้
- **ส่งเข้ากลุ่มพนักงาน:** สร้างกลุ่ม LINE → เชิญบอท OA เข้ากลุ่ม → **บอทจะทักบอก ID ของกลุ่มให้เองทันที** (หรือพิมพ์คำว่า `id` ในกลุ่มเมื่อไรก็ได้) → ใช้ค่านั้น

> ⚠️ **ห้ามใส่เครื่องหมายคำพูดครอบ** — ค่าถูกใช้ตรง ๆ ดังนั้น `"Cxxx"` จะไม่มีวันตรง
> ถ้าเว้นว่างไว้ = ปิดแจ้งเตือน (ระบบยังทำงานปกติ ไม่ error)

### ปุ่มเปลี่ยนสถานะบนการ์ดออเดอร์

การ์ดที่ push เข้าแชทร้านมีปุ่ม **กำลังทำ / พร้อมแล้ว / ยกเลิกออเดอร์** กดแล้วเปลี่ยนสถานะออเดอร์และแจ้งลูกค้าทาง LINE ทันที (ทำงานเหมือน dropdown ใน `/admin/orders` ทุกประการ)

**`LINE_ORDER_NOTIFY_TO` คือรายชื่อผู้มีสิทธิ์กดปุ่มนี้ด้วย** — การ์ดถูก forward ต่อได้ ระบบจึงเช็คซ้ำว่าคนกดอยู่ในแชทที่ตั้งค่าไว้ ถ้าไม่ใช่จะถูกปฏิเสธ

**ถ้ากดปุ่มแล้วไม่มีอะไรเกิดขึ้น** ไล่ตามลำดับนี้:

1. **พิมพ์คำว่า `id` ในแชทนั้น** — บอทจะตอบว่าแชทนี้ตั้งค่ารับออเดอร์แล้วหรือยัง ถ้าขึ้น ⚠️ ให้เอา ID ที่ได้ไปใส่ใน `LINE_ORDER_NOTIFY_TO` (Vercel → Settings → Environment Variables) แล้ว redeploy
2. **ถ้าบอทไม่ตอบคำว่า `id` เลย** แปลว่า LINE ไม่ได้ยิง webhook มา ให้เช็คใน console:
   - LINE Developers → Messaging API → **Webhook URL** = `https://www.lovepier.cafe/api/line-webhook` และ **Use webhook: ON**
   - LINE OA Manager → การตั้งค่าการตอบกลับ → **Webhook: ON** (สวิตช์เดียวกับ Use webhook — **ตัวนี้คือตัวที่ปิดบอทจริง**)
   - `LINE_MESSAGING_CHANNEL_SECRET` ต้องเป็น secret ของ channel **Messaging API** ไม่ใช่ของ LIFF/Login — ถ้าใส่ผิดทุก event จะถูกตีตกที่ signature check
   - สำหรับกลุ่ม: **Allow bot to join group chats: ON**

   > **แชท (Chat) ให้เปิด ON ไว้** — LINE เคยมีโหมด Bot/Chat ที่เลือก Chat แล้วปิด webhook แต่ปัจจุบันแยกเป็นสวิตช์อิสระ **Chat ON + Webhook ON ใช้ร่วมกันได้** และต้องเปิด Chat พนักงานถึงจะเห็นและได้แจ้งเตือนข้อความที่ลูกค้าส่งเข้ามา
3. **ดู Vercel logs** — ทุกครั้งที่กดปุ่มจะมีบรรทัด `staff postback: kind=… chat=… targets=…`
   - `kind=unauthorized` = ข้อ 1 (แชทไม่ตรงกับ env)
   - `kind=ok` = ทำงานแล้ว ไปดูข้อความที่บอทตอบกลับ
   - ไม่มีบรรทัด `LINE webhook events:` เลย = ข้อ 2 (LINE ไม่ได้ยิงมา)

## Rich Menu + คำสำคัญที่บอทตอบ

ปุ่มใน Rich Menu ต้องตั้งเป็น **ข้อความ (Text)** ไม่ใช่ลิงก์/LIFF เพราะ:
- ข้อความของลูกค้าจะขึ้นในแชท → พนักงานเห็นใน OA Manager และได้แจ้งเตือน
- การกดได้แปลว่าลูกค้าเป็นเพื่อน OA อยู่จริง → push (ใบเสร็จ/ยืนยันเงิน/แจ้งอาหารพร้อม) ส่งถึงแน่
- ถ้าเป็นลิงก์ LIFF จะเปิดหน้าสั่งเลย ไม่มีอะไรเข้าแชท และไม่ได้พิสูจน์อะไร

**⚠️ ข้อความต้องตรงกับตารางนี้เป๊ะ ๆ** ถ้าแก้ข้อความในเมนูแล้วไม่ตรง ปุ่มจะเงียบแบบไม่มีใครรู้ (ข้อความเข้าแชท บอทไม่ตอบ พนักงานตอบมือ) — คำที่รับได้อยู่ใน [lib/orderIntent.js](lib/orderIntent.js)

| ปุ่ม | ประเภทแอ็กชัน | ข้อความ | บอทตอบ |
|---|---|---|---|
| สั่งเดลิเวอรี | **ข้อความ (Text)** | `ขอสั่งเดลิเวอรี` | การ์ด "พร้อมรับออเดอร์แล้ว" + ปุ่มเข้าหน้าสั่ง |
| เช็กสถานะ | **ข้อความ (Text)** | `เช็กสถานะออเดอร์` | การ์ดสถานะออเดอร์ล่าสุด |
| เมนู | ลิงก์ | `https://lovepier.cafe/menu` | — |

ตั้งค่าอื่นใน **การตั้งค่าการตอบกลับ**:

| ตัวเลือก | ค่า | เหตุผล |
|---|---|---|
| แชท (Chat) | **ON** | พนักงานเห็น + ได้แจ้งเตือนข้อความลูกค้า |
| Webhook | **ON** | ตัวที่คุมบอทจริง |
| ข้อความต้อนรับเมื่อเพิ่มเพื่อน | **OFF** | ระบบส่งการ์ดต้อนรับเองแล้ว ถ้าเปิดทั้งคู่ลูกค้าได้ 2 ข้อความ |
| ข้อความตอบกลับอัตโนมัติ | **OFF** | ถ้ามี keyword ตรงกันจะตอบซ้อนกับการ์ด |

มือถือพนักงานต้องลงแอป **LINE OFFICIAL ACCOUNT** และเปิดแจ้งเตือน — เปิด Chat เฉย ๆ ไม่พอ

> ตั้ง Rich Menu **หลัง** deploy โค้ดเสมอ ไม่งั้นปุ่มจะไปตกใส่ webhook ที่ยังไม่รู้จักคำนั้น

## เช็คระยะจัดส่ง + โพสต์ออเดอร์เข้าแชท LINE (ทางเลือก)
หน้ากรอกข้อมูลมีปุ่ม **"📍 เช็คระยะจัดส่ง"** → ขอตำแหน่งลูกค้า → คำนวณ**ระยะขับจริง**จากร้านด้วย Google Routes API → โชว์ระยะ + เตือนถ้าเกินรัศมี (เตือนแต่ยังสั่งได้)
เมื่อเปิดจากในแอป LINE ระบบจะ **`liff.sendMessages()` โพสต์สรุปออเดอร์เข้าแชท** ให้อัตโนมัติ

**ตั้งค่าได้จากหน้า `/admin/settings` (ไม่ต้องแก้ env):**
- **วิธีคำนวณระยะ:** เลือกได้ 2 แบบ
  - **เส้นตรง (ฟรี)** — ไม่ต้องใช้ API key ใช้ได้ทันที
  - **ระยะขับจริง (Google)** — แม่นกว่า ต้องกรอก Google Maps API key (เปิด Routes API + billing)
- **พิกัดร้าน (Latitude/Longitude)** — เปิด Google Maps คลิกขวาที่ร้าน ก๊อปเลข 2 ชุด
- **รัศมีจัดส่ง (กม.)** — ค่าเริ่มต้น 5

> ยังไม่กรอกพิกัดร้าน = ปิดเช็คระยะ (ปุ่มยังกดได้ แต่บอกว่าเช็คไม่ได้ ให้ร้านเช็คเอง) — ระบบไม่ error
> ค่าเก็บในตาราง `settings` (คีย์-แวลู) อ่านผ่าน `lib/settings.js`; env `GOOGLE_MAPS_API_KEY`/`SHOP_LAT`/`SHOP_LNG`/`DELIVERY_RADIUS_KM` ยังใช้เป็น fallback ได้

## Badge ออเดอร์ใหม่ใน /admin
Sidebar จะขึ้น **ตัวเลขสีแดง** ข้างเมนู "ออเดอร์" = จำนวนออเดอร์ที่ยังสถานะ `รอชำระเงิน (pending)` — อัปเดตอัตโนมัติเมื่อเปลี่ยนสถานะ

## ไฟล์ที่เกี่ยวข้อง
- `components/CartDrawer.js` — UI เช็คเอาท์ 4 ขั้น
- `pages/api/orders.js` — บันทึกออเดอร์ + จำข้อมูลลูกค้า + แจ้งเตือน LINE
- `pages/api/customer.js` — ดึงข้อมูลลูกค้าเก่าจาก LINE userId
- `lib/promptpay.js` — สร้าง payload QR (มาตรฐาน EMVCo)
- `lib/liff.js` — LINE Login / ดึงโปรไฟล์
- `lib/lineMessaging.js` — push แจ้งเตือนออเดอร์ใหม่
- `app/admin/orders/` + `app/admin/actions/orders.ts` — หน้าดูออเดอร์ + เปลี่ยนสถานะ
- `lib/db/schema.ts` + `lib/db/orders.sql` — ตาราง orders/customers
